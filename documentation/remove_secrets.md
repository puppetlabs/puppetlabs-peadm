# Remove installation console passwords

The `peadm::remove_secrets_local` and `peadm::remove_secrets_primary` plans remove stored copies of the **installation console admin password only**. Despite their names, these plans are not a general secret scrubber. Run them after installation and any workflows that still need the installation password.

## Scope

| Plan | File | Fields removed |
| --- | --- | --- |
| `peadm::remove_secrets_local` | `params.json` on the Bolt controller (or the file selected with `params_file`) | Top-level `console_password` and `console_admin_password` |
| `peadm::remove_secrets_primary` | `/tmp/pe.conf` on `primary_host` | Top-level `console_admin_password` |

The installer calls its input parameter `console_password` and writes it into temporary `pe.conf` as `console_admin_password`. Local cleanup recognizes both spellings for the same console admin password. Nested fields are not removed.

**The running PE configuration is not touched.** In particular, `/etc/puppetlabs/enterprise/conf.d/pe.conf` stays unchanged, even if it contains a console password. The plans do not reset the admin account password, revoke tokens, restart services, or change LDAP, database or Code Manager credentials. They do not modify logs, inventory files, private-key files, backups or other hosts. Other inline credentials in `params.json` also stay unchanged.

**License files stay in place.** Neither the local source license nor `/etc/puppetlabs/license.key` is deleted or edited. License-related parameters are preserved in `params.json`.

## Usage

Both plans accept every parameter accepted by [install](install.md), so you can use the same install `params.json` with `--params @params.json`. Installer arguments are accepted for compatibility and are not used to reconfigure PE. Only `primary_host` selects the remote cleanup target. `console_password` is optional for cleanup, so both plans also accept the file after local cleanup has removed that key.

Run primary cleanup, then local cleanup:

```sh
bolt plan run peadm::remove_secrets_primary --params @params.json
bolt plan run peadm::remove_secrets_local --params @params.json
```

The local plan edits `params.json` relative to Bolt's working directory by default. `--params @some-file.json` loads arguments but does not tell the plan which source file Bolt loaded. When using another filename or directory, explicitly select that same file:

```sh
bolt plan run peadm::remove_secrets_primary --params @/secure/install-params.json
bolt plan run peadm::remove_secrets_local --params @/secure/install-params.json params_file=/secure/install-params.json
```

The local plan runs within the Bolt controller process and requires write access to the file and its directory. The primary plan runs a task using the primary's inventory transport and requires permission to replace `/tmp/pe.conf`; use the same privileged connection settings used for installation. It has no alternate configuration-path option.

Both files must be JSON objects, as generated by this project's installation workflow. Non-JSON HOCON is rejected without editing the file. Missing files or already-removed keys return `changed: false`; successful cleanup returns `changed: true` and the removed key names, never password values. Symbolic links and files with multiple hard links are rejected. Changes replace the file atomically, preserve ownership and file permissions, and create no backup containing the old password.

After local cleanup, `params.json` is no longer a complete install input: installation still requires `console_password`. Supply it again if reinstalling. Other plans accept only their own parameters; accepting the same installer file is a feature of these two cleanup plans, not of every PEADM plan.

Cleanup removes fields from the named files; it does not erase copies in logs, running configuration, version control, backups, filesystem history or existing Bolt execution records. The cleanup plans do not print the supplied installation arguments, but Bolt's own logging settings still apply when loading a parameters file containing secrets.

See [params.md](params.md#remove-secrets-local) for full parameters-file examples and links to the plan implementations.
